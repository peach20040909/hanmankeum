# 한만큼

> 각자가 한 만큼의 기록을 모아, 공정하게 참여한 만큼 평가받을 수 있도록 — Team HMK

팀 프로젝트가 끝나면 교수님은 "누가 무엇을 했는지"를 결과물과 상호평가만으로 판단해야 합니다.
한만큼은 GitHub·Notion에 흩어진 작업 기록을 모아, **교수님이 원래 쓰던 평가기준**에 맞춰 근거와 함께 보여 주는 웹 서비스입니다.

AI는 기록을 정리하고 분류만 합니다. 판단은 교수님이 합니다. 서비스는 성적을 산출하지 않습니다.

[서비스 바로 보기](https://hanmankeum.vercel.app/) · [프롬프트 문서](docs/prompts.md) · [개발·운영 안내](docs/development.md) · [MIT License](LICENSE)

팀 HMK: 박서준(팀장) · 장민준 · 김효준 — 2026 명지대 AI 리터러시 경진대회 결선작

## 직접 확인하기

### 배포 사이트에서

1. [hanmankeum.vercel.app](https://hanmankeum.vercel.app/)에서 **시연용 예시 팀 불러오기**를 누릅니다.
2. 마감된 팀의 기여도 리포트가 열립니다. 아래 순서로 보면 됩니다.

| 확인할 것 | 어디서 |
|---|---|
| AI가 분류한 건수, 사람이 확인해야 할 건수 | 리포트 위쪽 `AI가 한 일` |
| AI와 규칙이 엇갈린 기록 | 활동 근거 → `확인 필요` |
| 기여율이 계산된 과정 | `산출 기준 보기` |
| 기록 0건인 학생 처리 | 최민재 행 클릭 |
| 근거 검사에서 빠진 AI 문장과 이유 | 학생별 AI 요약 · 자기 기술 |
| 교수님께 내는 리포트 | `PDF 내보내기` |

시연 팀의 커밋·PR은 이 저장소의 실제 기록이고, 팀원 배정과 비율은 설명용 예시입니다.

## 어떻게 쓰나

| 시점 | 교수님 | 학생 |
|---|---|---|
| 학기 초 | 팀을 만들고 초대 링크를 보냅니다. 원래 쓰던 평가기준을 붙여 넣고, AI 초안을 고쳐 확정합니다. | 링크로 들어와 기준을 확인하고 의견을 남깁니다. |
| 학기 중 | 기록을 수집합니다. 점수는 보이지 않습니다. | 평소처럼 작업합니다. 알림·점수·순위가 없습니다. |
| 마감 후 | 리포트를 보고, 확인 필요 기록을 정리하고, PDF를 내려받습니다. | 자기 기술과 익명 동료평가를 한 번씩 씁니다. |

### 기여율 계산

기준 항목마다 "팀 전체 기록 중 이 학생 몫"을 구하고, 교수님이 정한 가중치를 곱해 더합니다.

```
기여율(i) = Σ_k [ r(i,k) × w(k) ]
r(i,k)   = 학생 i의 항목 k 기록 수 ÷ 팀 전체 항목 k 기록 수
w(k)     = 교수님이 확정한 항목 k의 가중치 (합 100)
```

- 팀 전체에 기록이 0건인 항목은 비율을 낼 수 없어서, 그 가중치를 나머지 항목에 비율대로 나눕니다.
- 자기 기술과 동료평가는 숫자에 넣지 않습니다. 리포트에 따로 보여 줍니다.
- 성적으로 바꾸는 계산은 하지 않습니다. 최종 평가는 교수님 몫입니다.

## AI에게 맡긴 일과, 그대로 믿지 않는 장치

Claude에게 맡긴 일은 세 가지입니다. 중요한 순서대로 적었습니다. 프롬프트 전문은 [docs/prompts.md](docs/prompts.md)에 있습니다.

### 1순위 · 기록 분류 (`criteria-classify-v1`)

작업 기록을 교수님 기준 항목 중 하나로 나누고, 이유를 한 문장으로 남깁니다. 맞는 항목이 없으면 '기준 밖'으로 둡니다.

- 같은 기록을 규칙(교수님이 정한 키워드·활동 종류)으로도 따로 분류합니다.
- 둘의 답이 다르면 **확인 필요**로 표시하고, 교수님이 원본을 보고 정할 때까지 남깁니다.
- 교수님이 바꿔도 AI의 원래 판단과 이유는 보존합니다.
- 둘이 같은 답을 내도 정답이라는 보장은 없어서, 일치한 기록도 일부는 확인하라고 안내합니다.

### 2순위 · 평가기준 정리 (`criteria-draft-v2`)

교수님이 쓰던 평가기준 글을 항목·가중치·키워드로 정리합니다. 발표 태도처럼 기록으로 확인할 수 없는 기준은 이유와 함께 뺍니다.

- AI 결과는 초안일 뿐이고, 교수님이 확정해야 저장됩니다.
- 서버가 항목 수, 활동 종류, 가중치 합을 한 번 더 검사합니다.

### 3순위 · 기여 요약 (`summary-v1`)

학생 한 명의 기록을 3~5문장으로 요약하고, 문장마다 근거 기록 번호를 붙입니다.

- 근거 번호가 없거나 틀린 문장, "성실하다" 같은 평가 표현이 든 문장은 서버가 뺍니다.
- 뺀 문장과 이유는 화면에 그대로 보여 줍니다.
- 서버는 근거 번호가 붙어 있는지만 확인합니다. 문장이 사실인지는 교수님이 원본을 열어 확인합니다.

### 그 밖의 장치

- **AI 도움 표시:** 커밋에 AI 공동 작성자나 `[AI]` 표시가 있으면 기록에 표시합니다. 감점이 아니라, 사람이 한 부분과 AI가 도운 부분을 구분해 보여 주는 정보입니다.
- **자기 기술 초안 (`selfdraft-v2`):** 학생 기록으로 초안을 만들어 주고, 학생이 얼마나 고쳤는지(수정률)를 교수님이 봅니다.
- **프롬프트 버전 기록:** 기록마다 어느 프롬프트 버전으로 분류됐는지 저장합니다.
- **AI 없이도 동작:** 호출이 실패하면 규칙으로 바꾸고 화면에 표시합니다.
- **AI에 보내는 것:** 기록 제목과 설명 앞부분만 보냅니다. 코드 본문과 Notion 문서 본문은 수집하지 않습니다.

AI로 작성한 코드를 사람이 어떻게 검토했는지는 [docs/ai-review.md](docs/ai-review.md)에 있습니다.

## 권한

- 팀을 만들면 교수 링크와 팀원별 초대 링크가 생깁니다. 서버는 링크 속 키로 역할을 구분합니다.
- 기준 확정, 기록 수집·조정, 리포트, 마감은 교수 링크로만 할 수 있습니다.
- 학생은 학기 중에 기록과 점수를 볼 수 없습니다.
- 동료평가는 교수 화면에도 '익명 A·B·C'로만 나옵니다.

## 앞으로

수강생 명단이 이미 학교 LMS에 있으니, LMS와 연결하면 팀 등록과 초대 링크 배포를 줄일 수 있습니다. 학교 기관 승인이 필요해 이번 범위에서는 뺐습니다. 단계별 계획은 [docs/development.md](docs/development.md)의 아래쪽에 있습니다.

## 코드 위치

|---|---|

| `notion.js` | Notion 웹훅 서명 검증 |
| `db.js` | 데이터베이스(Turso/libSQL) |
| `public/` | 화면 (프레임워크 없이 JavaScript) |
