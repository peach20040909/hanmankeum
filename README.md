# 한만큼

> 기억이 아니라, 기록으로 — Team 한만큼

팀 프로젝트가 끝나면 교수님은 "누가 무엇을 했는지"를 결과물과 상호평가만으로 판단해야 합니다.
한만큼은 GitHub·Notion에 흩어진 작업 기록을 모아, **교수님이 원래 쓰던 평가기준**에 맞춰 근거와 함께 보여 주는 웹 서비스입니다.

AI는 기록을 정리하고 분류만 합니다. 판단은 교수님이 합니다. 서비스는 성적을 산출하지 않습니다.

[서비스 바로 보기](https://hanmankeum.vercel.app/) · [프롬프트 문서](docs/prompts.md) · [개발·운영 안내](docs/development.md)

Team 한만큼 — 박서준(총괄·기획) · 김효준(AI 로직·프롬프트) · 장민준(서비스 구현·검수)
2026 명지대 AI 리터러시 경진대회 결선작

## 왜 만들었나

- 무임승차를 겪었다 **47.7%** · 해결 없이 수업이 끝났다 **72.2%**
- 명지대 교수님 네 분께 직접 여쭤봤을 때도 "일부가 편파적으로 평가하는 경우가 종종 있다", "수업 인원이 많아지면 직접 자세히 평가하지 못하는 점이 아쉽다"는 답이 돌아왔습니다.

출처: 김수연·김민정(2023), 『문화와 융합』 · 한만큼 팀 교수 서면 인터뷰(2026.09, 명지대 교수 4인)

처음에는 서비스가 정한 세 가지 기준(만들기·다듬기·이끌기)으로 기여를 나눴습니다. 그런데 왜 하필 그 세 가지인지 설명할 수 없었습니다. 그래서 **교수님이 원래 쓰던 평가기준을 그대로 쓰는 방식**으로 바꿨습니다.

## 직접 확인하기

1. [hanmankeum.vercel.app](https://hanmankeum.vercel.app/)에서 **시연용 예시 팀 불러오기**를 누릅니다.
2. 마감된 팀의 기여도 리포트가 열립니다. 아래 순서로 보면 됩니다.

| 확인할 것 | 어디서 |
| --- | --- |
| AI가 분류한 건수, 사람이 확인해야 할 건수 | 리포트 위쪽 `AI가 한 일` |
| AI와 규칙이 엇갈린 기록 | 활동 근거 → `확인 필요` |
| 기여율이 계산된 과정 | `산출 기준 보기` |
| 기록 0건인 학생 처리 | 최민재 행 클릭 |
| 근거 검사에서 빠진 AI 문장과 이유 | 학생별 AI 요약 · 자기 기술 |
| 교수님께 내는 리포트 | `PDF 내보내기` |

시연 팀의 커밋·PR은 이 저장소의 실제 기록이고, 팀원 배정과 비율은 설명용 예시입니다.

## 어떻게 쓰나

| 시점 | 교수님 | 학생 |
| --- | --- | --- |
| 학기 초 | 팀을 만들고 초대 링크를 보냅니다. 원래 쓰던 평가기준을 붙여 넣고, AI 초안을 고쳐 확정합니다. | 링크로 들어와 기준을 확인하고 의견을 남깁니다. |
| 학기 중 | 기록을 수집합니다. 점수는 보이지 않습니다. | 평소처럼 작업합니다. 알림·점수·순위가 없습니다. |
| 마감 후 | 리포트를 보고, 확인 필요 기록을 정리하고, PDF를 내려받습니다. | 자기 기술과 익명 동료평가를 한 번씩 씁니다. |

### 기여율 계산

항목마다 "내 기록 수 ÷ 팀 전체 기록 수"를 구하고, 교수님이 정한 비중을 곱해 모두 더합니다.

```
기여율(i) = Σ_k [ r(i,k) × w(k) ]
r(i,k)   = 학생 i의 항목 k 기록 수 ÷ 팀 전체 항목 k 기록 수
w(k)     = 교수님이 확정한 항목 k의 가중치 (합 100)
```

예) 시연 팀 박준호: 기능 구현 5/6 × 40% + 프로젝트 관리 1/3 × 20% = **40%**

- 팀 전체에 기록이 0건인 항목은 비율을 낼 수 없어서, 그 가중치를 나머지 항목에 비율대로 나눕니다.
- 자기 기술과 동료평가는 숫자에 넣지 않습니다. 리포트에 따로 보여 줍니다.
- 성적으로 바꾸는 계산은 하지 않습니다. 최종 평가는 교수님 몫입니다.

## AI에게 맡긴 네 가지 일

AI(Claude, `claude-haiku-5-5`)에게는 네 가지만 맡겼습니다. 결과는 모두 사람이 확인하는 초안입니다. 프롬프트 전문은 [docs/prompts.md](docs/prompts.md)에 있습니다.

| | 일 | 프롬프트 | 한 줄로 말하면 | 그대로 믿지 않는 장치 |
| --- | --- | --- | --- | --- |
| ① | 기준 정리 | `criteria-draft-v2` | "교수님 평가방식 그대로 사용해 줘" | 초안은 저장되지 않고, 교수님이 고쳐서 확정해야 저장 |
| ② | 기록 분류 | `criteria-classify-v1` | "평가하지 말고, 분류만 해 줘" | 규칙 분류와 다르면 '확인 필요'로 교수님께 넘김 |
| ③ | 기여 요약 | `summary-v1` | "문장마다 근거 기록 번호를 붙여 줘" | 번호가 없거나 틀린 문장, 평가하는 말은 코드가 자동 제외 |
| ④ | 자기 기술 초안 | `selfdraft-v2` | "기록에 없는 일은 지어내서 쓰지 마" | 학생이 고쳐 쓰고, 얼마나 고쳤는지(수정률)를 교수님이 봄 |

### ① 기준 정리

- 교수님의 평가 항목과 비율을 바꾸지 말고 그대로 쓸 것
- 발표 태도처럼 기록으로 확인할 수 없는 기준은 빼고, 기준을 뺀 이유를 적을 것

### ② 기록 분류

- 학생을 평가하지 말고, 기록을 교수님 기준 항목으로 나누기만 할 것
- 맞는 항목이 없으면 억지로 넣지 말고 '기준 밖'으로 둘 것
- 왜 그 항목으로 나눴는지 한 문장으로 적을 것

같은 기록을 규칙(교수님이 정한 키워드·활동 종류)으로도 따로 분류합니다. 둘의 답이 다르면 **확인 필요**로 표시하고, 교수님이 원본을 보고 정할 때까지 남깁니다. 교수님이 바꿔도 AI의 원래 판단과 이유는 보존합니다.

### ③ 기여 요약

- 기록에서 확인되는 사실만 쓰고, 문장마다 근거 기록 번호를 붙일 것
- "열심히", "뛰어난" 같은 평가하는 말과 다른 팀원과의 비교는 쓰지 말 것

AI가 쓴 문장은 코드(`generate.js`의 `validateSentences`)가 한 번 더 거릅니다.

| AI가 쓴 문장 (예시) | 붙인 근거 | 결과 |
| --- | --- | --- |
| "로그인 API를 구현했다" | 기록 3번 | ✓ 남김 |
| "성실하게 문서를 정리했다" | 기록 7번 | ✕ 자동 제외 · 평가하는 말 |
| "발표 자료를 만들었다" | 기록 99번 | ✕ 자동 제외 · 없는 기록 번호 |

제외한 문장은 이유와 함께 교수님 화면에 그대로 보여 줍니다. 코드는 근거 번호가 붙어 있는지까지만 확인하고, 문장이 사실인지는 교수님이 원본을 열어 확인합니다.

### ④ 자기 기술 초안

- 학생 본인 기록에 있는 일만 "저는 ~했습니다"로 쓸 것
- 기록에 없는 일은 지어내지 말고, 쓸 게 모자라면 문장 수를 줄일 것

### 그 밖의 장치

- **AI 도움 표시:** 커밋에 AI 공동 작성자나 `[AI]` 표시가 있으면 기록에 표시합니다. 감점이 아니라, 사람이 한 부분과 AI가 도운 부분을 구분해 보여 주는 정보입니다.
- **프롬프트 버전 기록:** 기록마다 어느 프롬프트 버전으로 분류됐는지 저장합니다.
- **AI 없이도 동작:** 호출이 실패하면 규칙으로 바꾸고 화면에 표시합니다.
- **AI에 보내는 것:** 기록 제목과 설명 앞부분만 보냅니다. 코드 본문과 Notion 문서 본문은 수집하지 않습니다.

## 직접 돌려 보고 고친 것

배포 사이트에서 예시 교수 기준 3종, 이 저장소의 실제 커밋·PR 75건, 실제 Notion 편집으로 직접 실행했습니다. 아래 값은 모두 실제 서비스에서 잰 것입니다.

| 문제 | 원인과 해결 | 결과 |
| --- | --- | --- |
| ① AI가 엉뚱한 키워드를 고름 | 'PR'처럼 모든 기록에 붙는 말을 키워드로 넣어 항목을 나눌 수 없었음 → 그런 말은 빼라고 프롬프트에 추가 | 문제 키워드 **26번 → 2번** |
| ③ AI 요약이 중간에 잘림 | 7번 중 3번 실패, 화면엔 'AI 미연결'뿐 → 실패 이유를 기록해 길이 한도 초과를 찾고, 최대 길이를 3,000 → 8,000토큰으로 늘림 | **5번 모두** AI 요약 성공 |
| ④ AI가 못 알아듣는 지시 | "대신 마지막 문장 없이 끝냅니다"는 무엇 대신인지 알 수 없음 → "쓸 사실이 모자라면 문장 수를 줄입니다"로 고침 | 뜻이 하나로만 읽히게 |
| 75건 중 47%가 어느 항목에도 안 맞음 | 버그·화면 수정을 넣을 항목이 교수님 기준에 없었음 → 억지로 넣으면 기여율이 틀어져서 AI가 판단하지 않게 둠 | 숨기지 않고 교수님께 넘김 |

애매한 지시는 AI가 무시하거나 엉뚱하게 따릅니다. **AI에게 정확히 전달하는 능력**도 AI 리터러시라고 보았습니다.

### 만든 AI와 검사한 AI를 나눴습니다

서비스 코드는 Claude Code와 함께 썼습니다. 검사는 코드를 쓰지 않은 Claude 별도 세션과 다른 회사 모델(GPT-6 ASTRA)에 따로 맡겼습니다. 보안 지적 7건과 사용자 관점 피드백 13건을 **사람이 하나씩 재현해 보고** 고쳤습니다. 자세한 내역은 [docs/ai-review.md](docs/ai-review.md)에 있습니다.

## 권한

- 팀을 만들면 교수 링크와 팀원별 초대 링크가 생깁니다. 서버는 링크 속 키로 역할을 구분합니다.
- 기준 확정, 기록 수집·조정, 리포트, 마감은 교수 링크로만 할 수 있습니다.
- 학생은 학기 중에 기록과 점수를 볼 수 없습니다.
- 동료평가는 교수 화면에도 '익명 A·B·C'로만 나옵니다.

## 한계와 다음 단계

- 아직 작은 표본입니다. 실제 수업에서의 효과는 확인 전입니다.
- 기록 밖 기여(발표, 현장 준비 등)는 학생 진술과 동료 증언에 의존합니다.
- **다음 학기 캡스톤 1과목**에서 교수님이 리포트를 실제로 참고하는지, 평가 시간이 줄어드는지 확인하려 합니다.
- 수강생 명단이 이미 학교 LMS에 있으니, LMS와 연결하면 팀 등록과 초대 링크 배포를 줄일 수 있습니다. 학교 기관 승인이 필요해 이번 범위에서는 뺐습니다. 단계별 계획은 [docs/development.md](docs/development.md)에 있습니다.
