# 결선 전 검증·시연 도구 구현 계획

> 실행: 이 세션에서 직접 구현하며 마지막에 독립 코드 검토를 받는다.

**목표:** 기존 설계와 프롬프트를 유지하면서 Notion 분류, 화면 흐름, 시연 도구를 자동 검증하고 PR로 전달한다.
**구조:** Notion 외부 조회만 기본값을 가진 의존성 인자로 분리한다. Playwright는 임시 파일 DB 서버와 로컬 실패 응답 제공자를 사용한다. 시연 도구는 동일한 교수 기준 흐름을 공유한다.
**기술:** Node ESM, node:test, libSQL, Playwright, 기존 Python 영상 도구.
**요구사항:** 2026-11-11 사용자 작업 명세(이 채팅).

## 제약

- 프롬프트 문자열·버전, 산식, 기존 테스트, 배포 환경변수는 변경하지 않는다.
- 추가 의존성은 Playwright 개발 의존성만 허용한다.
- 실키·토큰·운영 DB를 사용하지 않는다. 시험용 자격 문자열은 실행 중 생성하고 출력하지 않는다.
- tools/out/ 산출물은 git에서 제외한다. 기존 설계 문서는 안내 한 줄만 추가한다.
- PR과 최종 보고는 자동 확인 / 사람 확인 필요 / 미확인으로 구분한다.

## 검토 초점

- Notion 페이지 종류·작성자·팀 하위 범위·중복 이벤트가 실제 저장 결과에 반영되는가.
- 예시 기준 상태에서 학생 확인과 잠금이 모두 막히는가.
- 교수 조정 후 원래 분류가 유지되고 null 분류가 재조회 후에도 남는가.
- AI 실패가 DB/API/UI를 거쳐 요약과 초안에 모두 표시되는가.
- 녹화 도구가 과거 선택자·고정 타임코드 없이 끝까지 실행되는가.
