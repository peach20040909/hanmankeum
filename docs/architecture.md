# 구조와 데이터 흐름

2,230줄 · 런타임 의존성 2개(`@anthropic-ai/sdk`, `@libsql/client`). 프레임워크를 쓰지 않은 이유는 "무엇이 왜 그렇게 동작하는지"를 전부 설명할 수 있어야 평가 도구로 신뢰받기 때문입니다.

## 전체 흐름


## 경계: 무엇을 수집하고, 무엇을 AI에 보내는가

| 단계 | GitHub | Notion |
|---|---|---|
| **수집·저장** | 제목, 작성자, 시각, 원본 URL + 작성자가 직접 쓴 **설명문**(커밋 메시지 · PR/이슈 본문 · 코드 리뷰 댓글, 최대 4,000자) | 이벤트의 페이지 ID, 편집자, 시각, 변경 블록 수 + 페이지 제목·URL(토큰으로 조회) |
| **AI에 전달** | 제목 + 설명문의 **앞부분만** (분류 200자 · 요약 160자) | 제목과 메타데이터 |
| **수집하지 않음** | **코드 본문 · diff · 파일 내용** | **문서 본문 · 댓글 내용 · 대화** |

AI에는 기록의 제목과 메타데이터를 중심으로 보내고, 작성자가 쓴 설명문은 길이를 잘라 일부만 포함합니다.
**코드 diff와 Notion 문서 본문·댓글은 수집 단계에서부터 제외합니다** — 보내지 않는 게 아니라 애초에 가져오지 않습니다.

분류 요청은 기록 목록을 한 번에 묶어 보냅니다(`collect.js`의 사용자 메시지).

## 권한

계정이 없습니다. 추측 불가능한 초대 키 하나가 역할을 결정합니다.

```
crypto.randomBytes(18).base64url   →  teams.prof_key (교수) / members.key (학생)
요청 시  X-Key 헤더  또는  ?k=
```

- `profOnly` — 평가기준 입력·확정·잠금, 의견 처리, 기록 수집·조정, 리포트, 마감, 삭제
- `studentOnly` — 본인 확인·의견, 자기 기술, 동료평가
- 리포트는 마감 후에만, 교수만. 첨부 파일은 올린 본인과 교수만.
- 동료평가 응답자는 **교수 화면에도** `익명 A·B·C`로만 나갑니다. 실명 연결은 중복 제출 방지와 소명 목적으로 DB에만 남습니다.

## AI를 믿지 않기 위한 장치

| 장치 | 위치 | 동작 |
|---|---|---|
| 교차 확인 | `collect.js` `needsReview` | AI 분류 ≠ 규칙 분류 → `확인 필요`, 교수가 확정해야 해제. **일치는 정확성을 보증하지 않는다**(같이 틀릴 수 있음) |
| 근거 ID 연결 검사 | `generate.js` `validateSentences` | 인용 번호가 실재하는지 서버가 검증. 전부 없으면 문장째 제외, 일부만 틀리면 유효한 근거만 남기고 표시 |
| 평가 표현 차단 | `generate.js` `JUDGE` | 성실·능력·열심 등 기록으로 확인 불가능한 표현이 든 문장 제외 |
| 약한 연결 표시 | `generate.js` `overlap` | 문장과 인용 기록의 2글자 조각 겹침이 낮으면 `연결 약함` 표시 |
| 규칙 대체 | `collect.js` · `generate.js` | API 키가 없거나 호출 실패 시 규칙으로 전환하고 화면에 표시 |
| 학생 이의 | `POST /summary/objection` | 학생이 문장별로 남긴 이의가 교수 리포트에 함께 표시 |
| 초안 수정률 | `generate.js` `compareDraft` | AI 초안 대비 그대로·고침·새로 씀·지움과 전체 수정률(%) |

**AI는 점수를 매기지 않습니다.** 기여율은 공개된 산식으로만 계산합니다.

## 배포

```
public/*        정적 파일 (Vercel이 직접 서빙)
/api/*  ──────▶ api/index.js  →  handler.js의 handle(Request) → Response
                                        │
                                   db.js (libSQL / Turso)
```

같은 `handle`을 로컬에서는 `server.js`(node:http 어댑터)가 감쌉니다. 코드는 한 벌입니다.

서버리스 함수는 요청마다 새로 뜨므로 파일 DB를 쓸 수 없어 Turso(libSQL)를 씁니다. 스키마 생성과 컬럼 추가는 `db.js`의 `init()`이 인스턴스마다 한 번 실행합니다.
